# mitake-sms — 三竹簡訊內部發送工具

加我科技內部用的三竹簡訊（Mitake）發送介面與餘額監控，部署於 VPS。

## 這是什麼

- **Web 介面**：輸入手機號碼與訊息內容，一鍵發送簡訊
- **餘額告警**：定時查詢點數，低於門檻自動發 Telegram + Gmail 通知

## 為什麼需要它

三竹點數與 App 團隊共用（App 靠它發驗證碼）。過去要發簡訊得登入三竹後台操作，
要看餘額也得人工登入。此工具把兩件事都自動化，並在點數見底前主動示警。

## API 重點

| 端點 | 用途 | 成本 |
| --- | --- | --- |
| `SmQuery` | 查詢餘額 | 免費 |
| `SmSend` | 發送簡訊 | 1 點/則 |

- 認證：帳號密碼直接放請求參數（無 API Key 機制）
- **回應為 Big5 編碼**，用 UTF-8 硬解會亂碼
- 送出中文需帶 `CharsetURL=UTF-8`
- 中文簡訊 **70 字 = 1 則 = 1 點**，超過即倍增
- **單次發送上限預設 5 則**（`send_sms(max_segments=5)`），超過會在送出網路請求**之前**擋下並拋錯，不扣點。要送更長內容必須明確傳入 `max_segments=`
- 成功回應含 `statuscode=1` 與 `msgid`

### 失敗有兩種，不能一律當「請重試」

`MitakeAPIError` 帶 `possibly_charged`：

- `False` — 三竹明確拒絕，**沒扣點**，可安全重送
- `True` — 請求已送達三竹但結果未確認，**多半已扣點**；重送會扣兩次且對方收到兩封，必須改以 `msgid` 去三竹後台查證

呼叫端（尤其是 Web 介面）必須把這兩種渲染成不同畫面。詳見 `HANDOFF.md` §2.1。
